# Git e Pull Request

- A `main` é protegida: mudanças entram por Pull Request. Não faça push direto na `main`.
- Branch: `desafios/<slug-do-projeto>`, por exemplo `desafios/vaga-dev-backend-pleno-2026`. Use `docs/<assunto>` para mudanças só de README e `chore/<assunto>` para configuração.
- Commits seguem o padrão do histórico (`feat:`, `refactor:`, `docs:`, `chore:`), com a mensagem em inglês. Exemplos: `feat: add Vaga - Dev Backend Pleno 2026 challenges` e `docs: update root index`.
- Um projeto novo vai em um único PR com as pastas, os arquivos, o README do projeto e a linha nova no índice da raiz.
- A descrição do PR lista o projeto, as áreas e os arquivos adicionados, e confirma o checklist de [conteudo-publico.md](conteudo-publico.md).
- Antes de commitar, de dar push e de abrir o PR, mostre o resumo para a pessoa e peça confirmação. Lembre que o repositório é público.
